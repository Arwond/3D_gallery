## Features

- **Gallery front page** — paginated thumbnail grid, 25 models per page.
- **Clickable hashtags** — every model can carry tags; clicking a tag shows
  all models with that tag. Tags are visible on the gallery cards and in the
  viewer's info panel.
- **Thumbnails** — each model's first view (with its configured rotation) is
  rendered to a small JPEG next to the `.glb`. Auto-generated by
  `scaffold.ps1` and only re-rendered when the `.glb` changes.
- **3D viewer** — orbit / pan / zoom, wireframe toggle, grid toggle,
  fullscreen, per-model rotation correction with "Copy rot" to paste back into
  `models.json`.
- **Draco + Meshopt** — compressed GLBs are supported out of the box.
- **Browser history** — the Back button (and the mouse back button) returns
  you to the exact gallery page, tag filter, and scroll position you opened
  the model from.
- **No build step** — everything is static; GitHub Pages serves the files as-is.
- **Windows one-liners** — `scaffold.ps1` and `remove-model.ps1` cover the
  whole add / remove workflow including tag prompts and thumbnails.

## Layout

    index.html
    css/style.css
    js/main.js
    models.json                  <- list of models (generated, see below)
    models/<model-id>/<file>.glb
    models/<model-id>/thumb.jpg
    scripts/build-manifest.mjs   <- regenerates models.json from models/
    scripts/make-thumbnails.mjs  <- renders models/<id>/thumb.jpg
    tools/thumb.html             <- used only by make-thumbnails.mjs (local)
    tools/thumb.js
    scaffold.ps1                 <- add models + tags + thumbnails (Windows)
    remove-model.ps1             <- remove models (Windows)
    README.md
    package.json

Only `index.html`, `css/`, `js/`, `models.json`, and the files under `models/`
are actually served by GitHub Pages. Everything under `scripts/` and `tools/`
runs locally only; they are harmless to leave committed (they make it easy to
clone the repo on another machine and re-run the workflow).

## Quick start

If the repo already contains models:

    npm run serve
    # open http://localhost:3000

To add your first model:

1. Copy `My_Model.glb` into the project root.
2. Run `.\scaffold.ps1`.
3. Type the hashtags when prompted (e.g. `sculpture, artifact`).
4. `npm run serve` to preview.
5. `git add -A && git commit -m "add model" && git push`.

## Adding a model

Easiest (Windows PowerShell):

1. Copy the `.glb` file(s) into the project root (same folder as
   `index.html`).
2. Run `.\scaffold.ps1`.
3. For every model that has no tags yet, the script asks for hashtags:

       Tagging 1 model(s) that do not have tags yet.
       Enter hashtags separated by commas, e.g.: sculpture, artifact, stone
       The '#' is optional. Spaces inside a tag become hyphens.
       Leave blank to mark the model as intentionally untagged.

         0001 Boba   [0001-boba]
           # sculpture, artifact
           -> sculpture, artifact

4. The script renders `models\<id>\thumb.jpg` for each model whose thumbnail is
   missing or older than the `.glb`.
5. Commit and push.

What `scaffold.ps1` does, in order:

1. Moves every `*.glb` from the project root into `models\<model-id>\`, where
   `<model-id>` is the lowercased basename with runs of non-alphanumeric
   characters replaced by `-` (e.g. `0001_Boba.glb` → `0001-boba`). It refuses
   to overwrite a folder that already holds a `.glb` — run
   `.\remove-model.ps1 <id>` first, or rename the file.
2. Refreshes `models.json` via `scripts/build-manifest.mjs` (or a PowerShell
   fallback if `node` is not installed). Existing `name`, `rotation`, and
   `tags` are preserved. New models get the default rotation
   `[-90, 0, 120]`.
3. Prompts for tags on every model whose `models.json` entry has no `tags`
   field yet. This includes models added before the tagging feature existed —
   nothing gets skipped.
4. Renders thumbnails with headless Chrome/Edge.

What it does **not** do: it never writes `index.html`, `css/`, `js/`,
`package.json`, `README.md`, or any other site file. Your front-end changes are
never overwritten by running it again.

Non-interactive: `.\scaffold.ps1 -NoPrompt` skips the tag prompts. Models that
have no tags stay untagged (the prompt will appear again the next time you run
the script without `-NoPrompt`).

Manual (any OS, with Node installed):

    # move the .glb manually into models/<id>/, then:
    npm run manifest
    npm run thumbs

You still need to add the `"tags"` field by hand in `models.json`; see [Tags](#tags).

## Tags

Every model can carry a list of hashtags in `models.json`:

```json
{
  "id": "0001-boba",
  "name": "0001 Boba",
  "url": "models/0001-boba/0001_Boba.glb",
  "rotation": [-90, 0, 120],
  "tags": ["sculpture", "artifact"]
}
